# Monsoon renderer refactor

Draft for review. Today, `App.tsx` is 780 lines and all 26 files in `src/` sit at the same level. The first goal is to make one interaction easy to trace. When someone picks a place, one function should show what happens to the map, forecast panel, and open dialog. The details of drawing the globe, fetching weather, and dismissing the sheet can live with their respective features.

## Proposed layout

| Directory       | What belongs here                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/app/`      | `App.tsx`, toolbar, native dialog and sources view, local preferences, and base styles. Keep `src/main.tsx` as the renderer entry.                                                                                                                                                                                                                                                                      |
| `src/atlas/`    | `Atlas`, `Radar`, basemap, place-label layers, star rendering, and atlas CSS. One place to work on the globe.                                                                                                                                                                                                                                                                                           |
| `src/places/`   | Place and coordinate types, coordinate identity and formatting, suggested places, forward and reverse geocoding, and the search/saved place list.                                                                                                                                                                                                                                                       |
| `src/forecast/` | Forecast types, Open-Meteo provider and Reykjavík snapshot, text and unit formatting, and components shared across forecast views such as `Conditions`, `WeatherArt`, and the sky. Use `panel/` for the sheet and gestures, `overview/` for daily forecasts and period grouping, and `minutes/` for the explorer and interpolation. Keep `dayStory.ts` at the forecast level because both views use it. |
| `src/shared/`   | Existing UI primitives, solar calculations used by the globe and forecast, and the JSON request helper used by weather, geocoding, and radar. Add something here when it has consumers in multiple features.                                                                                                                                                                                            |

## Migration order

1. **Move the existing modules.** Use a move-only commit with import and path updates. Move the root App into `src/app/`, keep `weather.ts` intact under `forecast/` for this step, and keep CSS import order. Update the renderer tsconfig, tests’ explicit TypeScript and JSON imports, and the snapshot’s Prettier ignore path. Update the lazy sky import while preserving its load boundary. Moving `WeatherArt` changes both its Vite SVG glob and the string it uses to look up each icon. Moving `space.ts` changes the raw star catalogue import. Compile and open the packaged renderer to exercise both assets.
2. **Extract the three visible parts of App.** Give the toolbar its existing actions. Give the dialog its native open/close and focus behavior, with place search owning its input, debounce, and request cancellation. Give `ForecastPanel` the tabs, overview, minute view, loading/retry states, and collapsed bubble. Move existing markup and handlers together. Keep the sheet's drag handle, scroll targets, and animation attached to the same panel element. Stop here for a review of the component boundaries.
3. **Give state a clear owner.** Keep one `selectPlace` action in App. A map pick opens Overview and preserves the camera position. Search, saved places, and Home also request a camera move. Even selecting the same place should reopen Overview and cancel an in-flight dismissal. Keep panel commands and the selected tab available to that action. Pass the same responsive panel width to the panel and globe. Move forecast fetching, retry, and refresh into `useForecast(lat, lon)`, and saved-place/unit persistence into `usePreferences`. Keep the selected minute, chart hover, and animation frames local to their views.
4. **Separate the two jobs in `weather.ts`.** Move place identity, built-in places, and geocoding to `places/`. Keep forecast normalization, the seed, and the 15-minute cache with the Open-Meteo provider. Move the existing request helper to `shared/`. Keep each cache at module scope. This step is independently reviewable and can wait if the panel and folder changes solve the immediate problem.

## Decisions for review

- **Folder depth.** The draft nests the three forecast workflows because they already have distinct entry points. A single flat `forecast/` folder is a smaller first move if you prefer it.
- **Stopping point.** Steps 1–3 address App and navigation through the source. Step 4 also removes the radar and place search dependencies on the forecast module.
